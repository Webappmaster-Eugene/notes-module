# Модуль заметок - тестовое задание

Backend-модуль заметок: спроектированное API, схема Prisma и реализованная операция изменения
заметки. Пользователь работает только со своими заметками. Чужая и несуществующая заметка
отвечают одинаково.

Стек: TypeScript strict, NestJS 11, Prisma 6 (PostgreSQL), Vitest.

## Что где лежит

Проектирование API - в [API.md](./API.md). Схема базы - в
[prisma/schema.prisma](./prisma/schema.prisma), готовый SQL из неё - в
[prisma/schema.sql](./prisma/schema.sql). Реализованный метод - в
[src/notes/notes.service.ts](./src/notes/notes.service.ts) и
[src/notes/notes.repository.ts](./src/notes/notes.repository.ts). Ответы на вопросы задания - в
[ANSWERS.md](./ANSWERS.md). Принятые решения и слабые места - в [DECISIONS.md](./DECISIONS.md).
Структура модуля описана ниже.

## Проверка за две минуты

Нужен Node.js 20.19 или новее. Базу поднимать не нужно: тесты идут против подменённого клиента
Prisma.

```bash
npm install
cp .env.example .env      # строка подключения нужна Prisma CLI, соединение не открывается
npm run prisma:generate
npm run check             # prettier, prisma validate, tsc --noEmit и 18 тестов
```

Ещё две команды: `npm run test:mutation` вносит в рабочий код 12 дефектов по одному и проверяет,
что каждый роняет тесты. `npm run prisma:sql` пересобирает `prisma/schema.sql` из схемы.

## Суть реализованного метода

```ts
await this.prisma.note.update({
  where: { id: noteId, userId },
  data: payload,
});
```

Владение заметкой входит в условие запроса, а не проверяется отдельной строкой кода. Заметка
другого пользователя просто не находится: Prisma отвечает ошибкой P2025, репозиторий превращает
её в null, сервис - в ответ 404. Проверку нельзя забыть, потому что userId обязателен в
сигнатуре репозитория, и нельзя обойти, вызвав сервис мимо контроллера.

По слоям это разложено так. Контроллер занимается только транспортом: берёт userId из
аутентифицированного запроса, отсекает некорректный noteId до похода в базу, проверяет тело по
белому списку полей. Сервис держит правила операции: патч не может быть пустым, отсутствие
заметки и чужая заметка отвечают одинаково, наружу уходит не строка Prisma, а собранное
представление. Репозиторий - единственное место, знающее про Prisma; он выполняет запрос,
ограниченный владельцем, и переводит P2025 в null.

Почему выбраны именно такие решения и какие были варианты - в [DECISIONS.md](./DECISIONS.md).

## Тесты

18 тестов на Vitest. Они проверяют инварианты модуля, а не то, что Prisma умеет обновлять строку.

`tests/update-note.test.ts` проверяет, что меняются только переданные поля; что null очищает
содержимое, а отсутствие ключа его не трогает; что владение уходит в условие запроса; что лишние
поля патча не доезжают до базы; что чужая заметка отвечает 404 и при этом остаётся неизменной;
что ответ на чужую заметку неотличим от ответа на несуществующую; что пустой патч отклоняется без
обращения к базе; что прочие ошибки базы не выдаются за 404.

`tests/update-note-input.test.ts` проверяет обрезку пробелов, разное поведение null в content и в
title, лимит длины, отказ полю вне белого списка, общий вид ошибки проверки и отсечение
некорректного noteId.

Сам набор тестов проверен мутационным прогоном: `npm run test:mutation` вносит в рабочий код 12
дефектов по одному - снятие владения из условия запроса, 403 вместо 404, копирование патча
целиком, перестановку идентификаторов владельца и заметки, подмену любой ошибки базы на 404,
отключение белого списка и другие. Все 12 роняют прогон.

## Ограничения

По условию задания не делались фронтенд, регистрация и JWT, Docker и полноценное приложение.
Реализована одна операция из пяти, остальные спроектированы в [API.md](./API.md). Гарда
аутентификации нет, есть точка, куда он встраивается. Что осталось непокрытым и где решение
уязвимо - в разделах 2 и 3 файла [DECISIONS.md](./DECISIONS.md).
