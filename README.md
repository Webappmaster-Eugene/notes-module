# Модуль заметок — тестовое задание

Backend-модуль заметок: спроектированное API, схема Prisma и реализованная операция изменения
заметки. Пользователь работает только со своими заметками; чужая и несуществующая заметка
отвечают одинаково.

Стек: TypeScript strict · NestJS 11 · Prisma 6 (PostgreSQL) · Vitest.

## Проверка за две минуты

Требуется Node.js 20.19+. Базу поднимать не нужно: тесты идут против подменённого клиента Prisma.

```bash
npm install
cp .env.example .env      # строка подключения нужна Prisma CLI, соединение не открывается
npm run prisma:generate
npm run check             # prettier --check + prisma validate + tsc --noEmit + 18 тестов
```

Дополнительно:

```bash
npm run test:mutation     # вносит 12 дефектов в рабочий код и проверяет, что тесты их ловят
npm run prisma:sql        # пересобрать prisma/schema.sql из схемы
```

## Суть реализованного метода

```ts
await this.prisma.note.update({
  where: { id: noteId, userId },
  data: payload,
});
```

Владение — часть условия запроса, а не отдельная проверка в коде. Строка, не принадлежащая
пользователю, просто не находится: Prisma отвечает `P2025`, репозиторий превращает это в `null`,
сервис — в `404`. Проверку невозможно забыть, потому что `userId` обязателен в сигнатуре
репозитория, и невозможно обойти, зайдя мимо контроллера.

Дальше по слоям:

- **контроллер** — только транспорт: достаёт `userId` из аутентифицированного запроса, отсекает
  некорректный `noteId` до похода в базу, валидирует тело белым списком полей;
- **сервис** — правила: патч не может быть пустым, «нет заметки» и «чужая заметка» отвечают
  одинаково, наружу уходит не строка Prisma, а собранное представление;
- **репозиторий** — единственное место, знающее про Prisma; ownership-scoped операция и перевод
  `P2025` в `null`.

Почему именно так и какие были развилки — в [DECISIONS.md](./DECISIONS.md).

## Тесты

18 тестов на Vitest. Проверяются инварианты, а не то, что Prisma умеет обновлять строку:

| Файл                          | Что проверяет                                                                 |
| ----------------------------- | ----------------------------------------------------------------------------- |
| `tests/update-note.test.ts`   | меняются только переданные поля; `null` очищает содержимое, а отсутствие ключа — нет; владение уходит в предикат запроса; лишние поля патча не доезжают до базы; чужая заметка отвечает `404` **и остаётся неизменной**; «чужая» неотличима от «несуществующей»; пустой патч отклоняется без обращения к базе; прочие ошибки базы не выдаются за `404` |
| `tests/update-note-input.test.ts` | обрезка пробелов, `null` в `content` против `null` в `title`, лимит длины, отказ полю вне белого списка, единый конверт ошибки, отсечение некорректного `noteId` |

Набор проверен мутационным прогоном (`npm run test:mutation`): в рабочий код по одному вносятся
12 дефектов — снятие владения из предиката, `403` вместо `404`, копирование патча целиком,
перестановка идентификаторов владельца и заметки, подмена любой ошибки базы на `404`,
отключение белого списка и другие. Все 12 роняют прогон.

## Ограничения

По условию задания не делались: фронтенд, регистрация и JWT, Docker, полноценное приложение.
Реализована одна операция из пяти — остальные спроектированы в [API.md](./API.md). Гарда
аутентификации нет: есть точка, куда он встраивается. Что именно осталось непокрытым и где
решение уязвимо — разделы 2 и 3 в [DECISIONS.md](./DECISIONS.md).
